dpx_piprepper

Prep a stack of CompanionPi SD cards without touching a keyboard twice. Flash it, bless it, eject it, next card. The tool you run is called cardbless.

get started view on github

01what it does

A fresh CompanionPi card (Bitfocus Companion v5.x) has no admin user, no SSH and no static IP, so every card needs the same manual first-boot dance. cardbless does that dance for you. Each blessed unit boots with a known admin user, SSH on, a static per-unit IPv4 address and a unique hostname.

job 1

flash + bless

Write the CompanionPi image to the card first, then bless it.

job 2

bless

Card is already flashed. Write the per-unit user-data and network-config to its boot partition.

job 3

clean up over ssh

On a unit that has booted, delete the leftover cloud-init files so the password hash does not stay on the card.

how you drive it

One Python file, fully interactive: numbered menus and prompts, no flags, no config file. After each card it asks whether to prep another, so you can work through a stack back to back. You enter the details again for each card.

02setup

macOS is the target (Apple Silicon is the primary machine). The tool exits on any other platform. Linux support is a nice-to-have, not built.

quick start

git clone https://github.com/dubpixel/dpx_piprepper.git
cd dpx_piprepper
pip3 install pyyaml
python3 src/cardbless-v1.py

Flashing writes raw to the disk and needs admin rights, so you may be asked for your Mac password (sudo).

03walkthrough

The order of questions, in the order they appear. The prompt text below is what the tool prints; the answers are made-up examples.

  1. pick the job

    Flash then bless, bless only, or clean up over SSH. Type a number, or q to quit at any menu.

  2. pick the image (flash only)

    A numbered list of every .img and .img.xz found in ~/Downloads and its subfolders, with sizes. The last entry lets you type a full path instead.

  3. pick the disk (flash only)

    Only external, physical disks under the size cap are listed. You must type the disk identifier to confirm the erase.

  4. flash

    rpi-imager CLI if installed, otherwise xz + dd. Then it waits up to 30 seconds for the boot volume to mount at /Volumes/bootfs.

  5. bless prompts

    Admin username, password (typed twice, no echo), hostname, static IP, prefix length, gateway, then the optional tagged VLAN.

  6. confirm, write, eject

    You see a summary and answer y to proceed. The tool validates, writes, reads back, ejects the card and logs the result.

  7. next card

    It asks Prep another card? and starts over.

input rules

fieldrule
usernameLowercase letters, digits, hyphens, underscores; starts with a letter or underscore; up to 32 characters. Default dubpixel. companion is refused (it is Companion's own service account).
hostnameLetters, digits and hyphens; must start with a letter, no leading or trailing hyphen. No underscores. It becomes <hostname>.local over mDNS.
IP, prefix, gatewayValid IPv4; the IP and the gateway must both be inside the subnet you entered. The gateway is also written as the DNS server (these are local show networks).
passwordAsked twice, must match and not be empty. Hashed with openssl passwd -6; the plain text is never written.

clean up over ssh

Run this after the card has booted in the Pi. The cloud-init files hold the password hash on a world-readable FAT partition, and this step removes them.

  1. connect

    You enter the unit's IP, an SSH username (default dubpixel) and the password. The tool first removes any stale known_hosts entry for that IP, then connects and reads the hostname.

  2. confirm

    Remove user-data/network-config from <hostname>'s boot partition?

  3. remove

    Runs sudo rm -f /boot/firmware/user-data /boot/firmware/network-config on the unit and prints OK or FAIL.

Needs sshpass. It also skips strict host key checking for that first connection.

04safety

Writing to the wrong disk would wipe a drive, so this tool is paranoid on purpose.

before any flash

disk checks

Only disks from diskutil list external physical are considered. Internal and virtual disks are skipped, anything over 256 GB is refused, and you must type the disk identifier (for example disk6) to confirm.

before any bless

boot partition check

In bless-only mode the mounted volume must contain cmdline.txt, config.txt and meta-data. If none does, nothing is written; if several do, you pick one. Right after a flash, the tool instead waits for /Volumes/bootfs to appear with a cmdline.txt.

every write

validate and read back

Each rendered file is parsed with PyYAML before it touches the card, then read back and compared to what was intended. A mismatch aborts loudly.

on the card

files left alone

meta-data is untouched. A stray ip= in cmdline.txt is stripped, and stale userconf.txt, userconf and ssh files are removed. Nothing on the card is ever handed to Finder or Terminal.

what it does not protect you from

The blessed user gets passwordless sudo (NOPASSWD:ALL) and SSH password login is on. That is deliberate, so techs swapping cards under time pressure are not blocked on a sudo prompt. Run the cleanup step after first boot so the hash is not left on the card.

05vlan trunk mode

Optional, asked during bless. It joins one extra tagged 802.1Q VLAN alongside the main network. The default VLAN ID is 218.

not boot-tested yet

The VLAN option is new in v0.2.0. The generated network-config is rendered and validated as YAML, but it has not been booted from a card the tool blessed. Check ip -br a on the first unit before relying on it.

main network

untagged on eth0

Works on an access port, or on a trunk whose native VLAN is the main one. Do not create a tagged twin of the main VLAN: duplicate connected routes send traffic out the wrong interface.

extra vlan

tagged on eth0.<id>

A netplan VLAN subinterface with no gateway and no DNS, so it stays an isolated segment.

addressing choices for the extra vlan

choicewhat you get
link-localSelf-assigned 169.254.x.x, no configuration. This is how Dante devices address themselves.
static IPYou enter an IP and prefix (the prefix defaults to the main network's). A subnet that overlaps the main network is refused.
switch side

On a trunk port feeding the unit, the main VLAN must be the native (untagged) one, and the extra VLAN tagged. A single IP cannot serve both tagged and untagged versions of the same VLAN. Declining the prompt produces exactly the same network-config as before the option existed.

06what gets written

Two files on the boot partition, rendered per unit. This is the shape that booted and worked on a real card, with the password hash shown as a placeholder.

user-data

#cloud-config

hostname: comp-operator
manage_etc_hosts: true
timezone: America/New_York

users:
  - name: dubpixel
    groups: users,adm,dialout,audio,netdev,video,plugdev,cdrom,games,input,gpio,spi,i2c,render,sudo
    shell: /bin/bash
    lock_passwd: false
    passwd: "<SHA-512 crypt hash, $6$...>"
    sudo: ALL=(ALL) NOPASSWD:ALL

enable_ssh: true
ssh_pwauth: true

The timezone is fixed in the script (America/New_York). The first line must be the literal #cloud-config or cloud-init ignores the file.

network-config

network:
  version: 2
  renderer: NetworkManager
  ethernets:
    eth0:
      dhcp4: false
      addresses:
        - 10.196.11.25/15
      routes:
        - to: default
          via: 10.196.11.1
      nameservers:
        addresses: [10.196.11.1]

with the vlan option (link-local)

  vlans:
    eth0.218:
      id: 218
      link: eth0
      dhcp4: false
      link-local: [ipv4]

This block is appended under the same network: key. For a static address, link-local: [ipv4] is replaced by an addresses: list.

how it boots

CompanionPi images are built on Raspberry Pi OS Lite arm64 (Debian Trixie). Images from late November 2025 on use cloud-init for first boot: network-config is written into netplan, which renders to NetworkManager (connections show in nmcli with a netplan- prefix). The FAT boot partition mounts on macOS as /Volumes/bootfs. The root filesystem is ext4 and not readable on macOS, so everything goes through the boot partition. cmdline.txt is left stock, with no ip= parameter.

07gotchas

Learned the hard way. Most of these are why the tool behaves the way it does.

symptom or trapwhat is going on
Never double-click files on the boot partitionFAT has no permission bits, so macOS treats every file as executable. Finder hands it to Terminal and runs it. A second try is blocked by Gatekeeper with a misleading "damaged" message. The tool never opens these files; you should not either.
No network config after bootAn earlier manual attempt pasted the shell heredoc lines (cat > ... << 'EOF' and EOF) into network-config, producing invalid YAML. PyYAML validation plus read-back catches this class of error.
Password hash is wrong or emptyA $6$... hash is expanded by the shell unless single-quoted or written through a quoted heredoc. The tool writes it from Python directly.
Static IP ignoredA kernel ip= parameter in cmdline.txt is the wrong mechanism on this OS; cloud-init's network-config is the right one. The tool strips a stray ip= and never adds one.
Username companion refusedThat is the service account Companion runs as. Pick another name.
"No openssl with -6 support found"brew install openssl@3. The tool looks for the Homebrew copy before the system one.
"No mounted volume looks like a Pi boot partition"Mount the card first. The volume needs cmdline.txt, config.txt and meta-data.
No eligible external disks foundInsert the card. Disks must be external, physical and under 256 GB.
Cleanup says it needs sshpassbrew install sshpass.
dot_clean errors on the cardIt routinely complains about macOS's own hidden folders on FAT volumes. That is expected, so the tool hides its output.
rpi-imager's cloud-init flagsNot used. On macOS they have a known bug (rpi-imager issue #1385) where the files are never copied, so the tool always blesses the card itself afterward.

the run log

Every blessed card appends one line to cardbless.log in the project folder: a timestamp, OK or FAIL, the hostname, IP and disk. It is gitignored and stays local.
